

#  Git Branching: Hands-on Practice — Create, Switch, Commit & Push  

---

## Learning Goals

By the end of this session, you should be able to:

- Understand what a branch is and why we use it
- Create, switch, list, and delete branches
- Make commits on a feature branch
- Merge a feature branch into `main`
- Use both modern (`git switch`) and older (`git checkout`) commands

---

## 1. Why Do We Need Branching?

### Problems without branching:
- Everyone works directly on the `main` branch
- One person’s mistake can break the entire project
- Difficult to experiment safely
- Hard to work on multiple features at the same time

### Solution – Branching:
- Keep the `main` branch stable and clean
- Develop new features on separate branches
- Merge the feature into `main` only when it is ready and tested

### Simple Analogy:
- **`main` branch** = Main road (should always be safe and usable)
- **Feature branch** = Side road where you can freely experiment
- **Merge** = Joining the side road back to the main road when the work is complete

---

## 2. Important Concepts

| Concept            | Simple Meaning                                      |
|--------------------|-----------------------------------------------------|
| Branch             | An independent line of development                  |
| `main` (or master) | The default / stable branch                         |
| Feature Branch     | Temporary branch created for a new feature or fix   |
| Switching Branch   | Moving your working directory to another branch     |
| Merge              | Combining the work of one branch into another       |

---

## 3. Essential Branching Commands

### View branches
```bash
git branch
```
- Shows all local branches
- The branch with `*` is the current branch

### Create a new branch
```bash
git branch feature-login
```

### Switch to a branch

**Modern way (recommended):**
```bash
git switch feature-login
```

**Older/alternate way:**
```bash
git checkout feature-login
```

### Create + Switch in one command (Most Useful)

**Modern way:**
```bash
git switch -c feature-login
```

**Older/alternate way:**
```bash
git checkout -b feature-login
```

> Both commands do the same thing: create a new branch and switch to it immediately.

### Switch back to main
```bash
git switch main
# or
git checkout main
```

### Merge a feature branch into main
```bash
git merge feature-login
```
- You must be on the `main` branch before running this command
- It brings all commits from `feature-login` into `main`

### Delete a branch (after merging)
```bash
git branch -d feature-login
```
- Use `-d` for safe delete (only works if the branch is fully merged)
- Use `-D` to force delete (even if not merged)

## 4. Complete Branching Workflow

```bash
# 1. Check current branch
git branch

# 2. Create and switch to a new feature branch
git switch -c feature-about
# OR
git checkout -b feature-about

# 3. Make changes (create/edit files)

# 4. Stage and commit on the feature branch
git add .
git commit -m "Added about page"

# 5. Switch back to main
git switch main

# 6. Merge the feature branch
git merge feature-about

# 7. Delete the feature branch
git branch -d feature-about

# 8. Verify
git branch
git log --oneline
```

---

## 5. Important Rules

1. **Never develop new features directly on `main`**
2. Always create a feature branch first
3. Always **commit your work** before switching branches
4. Merge the feature branch into `main` only when the work is ready
5. Delete the feature branch after successful merge
6. Prefer `git switch` and `git switch -c` (modern commands)

---

## 6. Common Mistakes & How to Avoid Them

| Mistake                        | What happens                      | Solution                              |
|--------------------------------|-----------------------------------|---------------------------------------|
| Forgot to switch branch        | Commits go to the wrong branch    | Always run `git branch` to check      |
| Trying to delete unmerged branch | Error: branch not fully merged  | Merge first, then delete              |
| Working directly on `main`     | Main branch becomes unstable      | Create a feature branch first         |
| Switching without committing   | Warning about uncommitted changes | Commit or stash before switching      |

## 7. Quick Revision

| Action                        | Modern Command              | Older Command                |
|-------------------------------|-----------------------------|------------------------------|
| List branches                 | `git branch`                | `git branch`                 |
| Create + Switch               | `git switch -c branch-name` | `git checkout -b branch-name`|
| Switch branch                 | `git switch branch-name`    | `git checkout branch-name`   |
| Merge into current branch     | `git merge branch-name`     | `git merge branch-name`      |
| Delete branch                 | `git branch -d branch-name` | `git branch -d branch-name`  |

---

## 8. Key Takeaway

> **Never work directly on `main` for new features.**

**Correct flow:**
```
Create feature branch → Work → Add → Commit → Switch to main → Merge → Delete feature branch
```
